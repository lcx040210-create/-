# X工作者之家 设计文档

- **日期**：2026-10-14
- **状态**：设计评审通过（六节设计逐节确认），待出实施计划
- **项目**：`x-workers-home`（新仓库，尚未初始化；技术骨架照 english-platform）
- **一句话**：面向 X 中文区的商单撮合平台——发单方发布推广任务，接单方在 X 上交付，平台托管资金、自动核验、撮合结算。

---

## 1. 背景与定位

- **对标**：灯塔、tutti、薪火（Web3 商单/任务平台）。社区反馈的命门：「稳定出单、靠谱结算、体验」。
- **差异化主攻**：门槛低体验好（低提现门槛 50 XM、充值 1:1 零损耗、规则透明）、靠谱结算（托管 + 限时确认 + 超时自动放款 + 提现全人工把关）。
- **叙事注意**：费率不便宜（全链路 ≈18.6%），「便宜」不加在费率上打，打在充值零损耗、提现门槛低、规则透明。
- **冷启动**：自然增长路线——1.0 必须全自助（无手把手支持），内置传播机制（免登录浏览、分享页、邀请返佣）。
- **主体**：建议注册海外主体（运营者自行落实）；1.0 先上服务条款与免责协议。

## 2. 角色与账号体系

**角色**：发单方（商家）、接单方（创作者）、平台（运营者，1.0 单 admin；「仲裁者」为后期角色，仅台账预留）。

**一个账号双身份**：人人可发单、可接单。

**注册（双绑定硬前置）**：钱包签名建号 → 绑定 X 账号（验证码放 bio 或发带码推文，爬虫复核）。两类绑定齐备后方可发单/接单/充值/提现；纯浏览（大厅、单详情、公开主页）免登录。

**登录**：钱包签名（EVM 签名，BSC 地址），无密码。1.0 不做邮箱等备选。

**绑定约束与安全**：
- 一个 X 账号、一个钱包地址各自只能绑定一个站内账号（防小号刷返佣）。
- 改绑（钱包/X）= 风控事件：重新签名验证 + 24h 冷静期（冷静期内禁止提现）+ 后台人工审核。

**账户评级（公开，两层）**：

1. **账号评级**（客观，X 数据）：入驻时爬取（粉丝量、账号年龄、平均浏览量、互动量、关注/被关注比等）自动出评级；每周刷新；刷粉特征（低互动高粉丝等）加重扣分。
2. **信用记录**（行为，站内）：平均评分（双向互评）、完单数、违约记录、新人标。

展示位：大厅单卡、单详情、公开主页。建单预留「最低评级要求」字段，1.0 默认关闭（不启用门槛）。

## 3. 商单与状态机

**商单字段**：类型（1.0：发帖 / 评论 / 引用；评论、引用类需指定目标推文）、要求（必须含关键词/话题标签/@/链接等）、每个名额价格 P、名额数 N。交付时限与确认窗全站固定（不按单配置）。

**预算与冻结**：下单冻结 = P × N × 1.05（含 5% 发单费）。

**生命周期**：

1. 商家建单（已充值的 XM 冻结）→ **自动上架**（无人工审核），大厅自动更新
2. 接单方抢单占名额（并发安全：名额不超卖）→ **3h 倒计时**开始
   - 3h 未交付 / 主动放弃 → 名额释放回池 + 记一次违约
   - 名额招满 → 停止招募
3. 交付 = 在 X 发出内容 + 站内提交链接（核验异步进行）→ 系统自动核验（§5）
   - 不通过 → 打回，窗口内可改可重交，**不重新计时**
   - 通过 → 进入 **48h 确认窗**
4. 48h 内：商家确认 → 放款；无动作 → **超时自动放款**；发起争议 → 该笔冻结（§5）
5. 完单 → 双向互评（5 星 + 可选文字），平均分公开

**保护与处置**：

- 商家下架/取消：**从未有人接单** → 全额退（含发单费）；**已有接单** → 发单费不退，仅退未接名额的预算；已接名额必须走完（不能砍 KOL）。
- KOL 违约计数累积到阈值 → 暂停接单（阈值实施期定稿）。
- 放款前系统复检帖子存活；放款后 **7 天内**商家可举报删帖 → 从余额追回（追不回记信用）。

## 4. 资金体系

**XM**：站内记账单位，1:1 锚 USDT，不可转让/互转。资金三态：可用 / 订单冻结 / 已结算。

**链条**：单链 **BSC**（USDT-BEP20）。充值、提现均与绑定钱包绑定。

**费率（三处）**：

| 环节 | 费率 | 说明 |
| --- | --- | --- |
| 充值 | 0% | 1:1 记 XM（最低 10 U 提示性下限） |
| 发单 | 5%（商家侧） | 冻结 = 预算 × 1.05 |
| 完单 | 5%（接单侧） | 接单方到手 0.95 × 单价 |
| 提现 | 10%（谁提谁付） | 100 XM → 90 USDT，链上 gas 平台承担 |

- **全链路示意**：充 105 U → 发 100 的单 → KOL 到手 95 XM → 提现拿 85.5 U；平台三处合计 19.5 XM（以充入为分母 ≈18.6%）。
- **XM 站内循环**（KOL 赚了 XM 再发单/消费）不产生提现费——后续玩法伏笔。

**充值**：平台固定收款地址；系统按链上转账的 **from 地址**自动匹配绑定用户 → 1:1 自动记账；匹配不上的挂后台人工处置（认领）。

**提现**（**全人工审核，绝不自动化——写死**）：

- 只能提到绑定钱包；≥ **50 XM**；**整十数**（50、60、70…）
- 每用户 **24h 限一笔**（按上一笔申请时间滚动计算）；被平台驳回的可立即重发（不吃冷却）
- 流程：申请（立即扣款、算出实付 90%）→ 后台审核队列 → admin 人工打款 → 填 txid 完成
- 首提 + 新地址（改绑后）人工多看一眼

**放款**：核验通过 +（商家确认或 48h 超时）→ 按单价 P 放款：接单方到手 0.95P、0.05P 入平台账户；争议则冻结至裁定。

**返佣（邀请制）**：

- 每个用户一个邀请码；被邀请人产生的**平台手续费**按档位返给邀请人：默认 **20%**，邀请满 **5 人 30%**，满 **10 人 40%**（封顶 40%）
- 以 XM 发放、可提现；平台记「营销支出」入对账
- 返佣基数是手续费（发单费/完结费/提现费），**不是单值**

**没收**：违规单处置（§5）中「没收全部余额、不予退还」为平台规则，写入服务条款。

**对账铁律**（后台对账页，自动巡检报警）：

- 钱包余额 ≥ 站内 XM 总量 × 90% + 处理中提现（XM 总量含可用 + 冻结；「×90%」即用户全部提现时的最大兑付）
- 钱包余额 − 上式下限 = 平台已赚、可提走的收入（三处手续费 + 没收款 − 已发返佣）
- 平台账户流水单列：发单费 / 完结费 / 提现费 / 返佣支出 / 没收

## 5. 核验、争议与处置

**核验 worker**（无 X API，抓取方案平台化）：

- 硬指标：帖子存在、作者 = 绑定账号、内容长度下限（评论类 **>10 字符**，按单类型可调）、含要求元素（关键词/话题标签/@/链接）、存活
- 策略：直接抓交付链接 + 拉账号时间线比对；队列 + 重试；反复失败降级「人工待核」，不卡死交易
- 证据：每次核验存快照（文本/截图）留档，争议时呈堂

**申诉**：接单方对「核验不过」可申诉 → 人工复看。

**争议**：

- 双方均可发起；商家须在 48h 确认窗内发起
- 流程：双方提交陈述/证据（建议 24h 证据窗口）→ admin 终审 → 判定「放款」或「退回预算」
- 预留「仲裁者」（闲鱼小法庭式：随机抽高信用用户投票）；1.0 不实现，仅台账预留

**抽查与罚则**：

- admin 随时抽查任意商单（随机 / 筛选 / 搜索）
- 认定不当（骚扰、暴力、诈骗等；**审核标准由运营者定稿**）：下架违规单 + **没收该账号全部余额（不予退还）** + 封号
- 善意已交付的 KOL 由平台从没收款中按单值补发（保护劳动者信任）
- 服务条款（含违规定义、处置规则、免责声明）注册强制勾选；条款版本化管理

## 6. 后台管理（admin）

按使用频率排序：

1. **提现审核队列**（首位；展示：用户、绑定地址、金额/实付、首提标记、24h 内记录、风险标；操作：通过→打款→填 txid / 驳回→填理由）
2. **充值核对**（仅未匹配项）
3. **抽查工具 + 罚则执行**（下架 / 没收 / 封号）
4. **争议裁决证据台**
5. **用户管理**（封禁、违约记录、改绑审核、评级查看）
6. **对账页 + 巡检报警**
7. **条款管理**（版本、公告）
8. 站内通知

## 8. 技术架构

- **技术栈**（复用 english-platform 模式）：NestJS + TypeORM + PostgreSQL + Redis + JWT + Next.js 14 + Tailwind
- **后端模块**：auth / bindings / users（含 ratings）/ orders / slots / deliveries / verification（worker）/ ledger / deposits / withdrawals / referral / disputes / reviews / notifications / admin / terms
- **核验 worker**：独立进程 + 队列 + 重试 + 降级
- **定时任务**：3h 超时释放+违约 ｜ 核验队列 ｜ 放款前存活复检 ｜ 48h 自动放款 ｜ 评级周刷新 ｜ 对账巡检
- **部署**：海外 VPS，docker-compose（Postgres + Redis + API + Worker + Web + Caddy 自动 HTTPS）+ 每日备份
- **测试重点**：资金守恒（冻结/放款/退款/没收逐笔对账）、抢单并发不超卖、提现规则（24h / 整十 / 全人工流程）、核验 worker 固定样本可复现、状态机全路径

## 9. 1.0 边界与成功标准

**做**：注册双绑 → 评级 → 大厅（免登录可逛）→ 抢单 → 3h 交付 → 自动核验 → 48h 确认/自动放款 → 互评 → 提现（人工审核）→ 对账 → 返佣 → 争议终审 → 抽查/罚则/条款。全闭环、全自助。

**不做**：

- 1.1+：TG 播报、仲裁者多人裁定、最低评级门槛启用、榜单、多链、评级算法细化
- **永久不做**：站内聊天/私信（减少绕单载体；保留举报入口 + 条款保留反绕单处置依据）、**任何形式的自动出金**、XM 互转

**成功标准（提案）**：首月 ≥20 笔真实闭环（非自导自演）、≥3 个自然到来的商家、提现 24h 内全到账、对账零差额。
